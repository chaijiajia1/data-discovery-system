## 覆盖网格与约束

覆盖网格 = 口径（`calibers`）× 通道（`channels`）。`pending_pairs` 是待覆盖的 (口径, 通道) 对，`covered_by_injection` 是预注入知识已覆盖的。
一个召回节点查询一个或多个口径（`targets`，可以写多个，也可以不写表示全部口径），经其角色的通道：单通道角色查一个通道，`omni_discovery` 一个 Agent 依次查全部通道。

硬约束（违反任一条的提案会被剔除）：
- 峰值并发（按依赖尽早开始的排程，同一时刻同时运行的节点数）不超过 `max_parallel`；各角色同时运行的节点数不超过其 `max_concurrency`。
- `required_dims` 里每个评估维度都必须有至少一个节点提供（见各角色的「提供维度」）。评估维度由召回角色内联提供（原选择类角色已并入）：bi = grain_fit / freshness，lineage = dim_coverage，caliber = caliber，omni = 全部；省掉能提供某个维度的角色会导致不可行。
- 所有角色都是召回类（phase=recall），写 `targets`（口径名，必须来自 `calibers`）；不写表示全部口径。
- 边只能连接你声明过的节点，不得成环。`kind` 取 `dep`（等待上游产出）或 `then`（仅顺序）。
- 节点 id 约定：`角色名@口径1+口径2`。

## 打分（供你权衡，系统会重算）

Score = α·Cov + β·Par − γ·Cost，权重见 `weights`，三项都已归一：
- `Cov` = 覆盖的 (口径, 通道) 对数（含 `covered_by_injection`）/ 总对数。覆盖越全越好，覆盖不是硬约束，但权重最大。
- `Par` = (W − M)/(W − 1)：W = 总工作量（每个召回节点的工作量 = 它处理的「口径 × 通道」对数；没有待覆盖对时只做核验的节点为 1），M = 按依赖排程后的完工时间。并行越多、M 越小，Par 越高。
- `Cost` = Agent 数 / (待覆盖对数 + 评估维度数)。Agent 越少越好。

取舍：批量节点（一个 Agent 带多个口径）与 `omni_discovery` 省 Agent，但节点内部串行、拉长 M；单通道单口径节点多 Agent 但并行度高。同一对重复探查不增加覆盖，只增加成本。
