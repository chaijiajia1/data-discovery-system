## 数据资产定位

取数、查数、指标口径、资产发现类问题，对**每个指标**按以下顺序判定。命中即停，不满足才降级。

### L0 · 会话内已确认资产

上下文中已有合法 BI 链接、已确认的 dataset_id / chart_id，或本会话已完成过同口径取数——直接复用，不重新定位。（上面「会话内已确认资产」非空的指标即属此级，系统已处理，不要改动。）

### L1 · 注入知识已指明资产

`<recalled_knowledge>` 中存在同时满足以下三条的知识块，按其指向的资产取数：

- chunkSummary（知识正文）指明了数据源资产（如「数据集 RedBI 26200」「实时DAU汇总看板」）
- 该知识描述的指标定义与本次问题所问的指标一致（允许同义 / 别名，如「日活」即 DAU）
- 本次问题所需的过滤条件与返回字段，chunkSummary 已说明，或本次问题不需要

score 只作参考，不作判据：低分知识若口径明确一致同样可用，高分知识若口径不符一律不用。

### L2 · 取知识全文核对

L1 命中了资产但**口径存疑**时，需取知识全文核对，通过后才能取数。口径存疑指：指标同名但定义可能不同、口径描述被截断、必填过滤或维度说明不完整；预注入阶段发现的「同名指标口径冲突」也属于存疑。

chunkSummary 完全没有指向任何资产时**不属于 L2**，直接判 L3——取全文不会凭空产生资产。

### L3 · 资产召回

以上均不满足：知识没有指向资产、指向的资产不满足上面「至少需要」的要求、或口径与问题不符——需要重新召回资产。

## 输出：把 L0–L3 映射成覆盖状态

| 你的判定 | `status` | 含义 |
|---|---|---|
| L0 / L1 | `covered` | 知识已指明所需的全部资产类型，口径一致，无需召回也无需核对 |
| L2 | `doubtful` | 命中了资产，但口径存疑，需核对 |
| L3 | `uncovered` | 需要召回 |

维度子目标没有 L0–L3，按此判：知识已把它绑定到资产字段 → `covered`；只有定义、没有绑定资产 → `doubtful`；知识没覆盖 → `uncovered`。

仅输出 JSON（无围栏、无解释）：

`{"goals": [{"kind": "metric|dimension", "name": "子目标名（与上面一致）", "status": "covered|doubtful|uncovered", "reason": "一句话理由：先写命中的级别（如 L1 / L2 / L3），再引用知识 id", "asset_ids": ["covered / doubtful 时：知识里已有的资产 id，不得编造"]}]}`

每个子目标输出一条。`asset_ids` 必须来自上面 `<recalled_knowledge>` 里出现的资产 id；`uncovered` 时可为空。
